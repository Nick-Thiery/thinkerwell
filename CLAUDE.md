# Thinkerwell

A free social-studies course, "Exploring Our World": 24 lessons in 4 sections, each lesson in five stages (Read, Write, Speak, Watch, Reflect), plus a short check at the end of each section. It is for refugee, displaced and under-served young people, about 10–17, most of them learning English. The first pilot is with HELP for Refugees, a refugee-led learning centre in Jakarta, on shared laptops and tablets with unreliable internet. The team is Justin Park (founder and director, content) and Nick (CTO, build). Background: `docs/PRODUCT.md`.

## Rules that are never traded away

1. **Privacy.** No accounts, no passwords, no email from learners, no ads, no third-party analytics, trackers or fonts loaded from other servers. Learner data stays on the device, except in a work file that someone saves themselves in Settings to move it to another device; nothing is ever uploaded. Recordings are never uploaded and never go in that file. The site never asks learners about their journey, home country, family, religion or ethnicity.
2. **Works on bad internet.** After the first visit the whole course works offline. Every save is local first. Videos are optional and every video has a written version ("Read instead").
3. **Nothing is locked.** Any lesson and any stage can be opened in any order. Quick checks and section checks never block progress, have no timers and can be retried. Wrong answers say "Not quite" in burnt orange with a hint; there is no red anywhere in learning flows.
4. **Shared devices.** Home asks "Who's learning today?" with a tile per learner. Each learner's work is separate. Anyone can "Just look around" without saving.
5. **Accessible.** WCAG 2.2 AA. Tap targets at least 44px, visible focus on everything, full keyboard use, `prefers-reduced-motion` respected, nothing below 14px, reading text 20px/32px at most 68 characters wide.
6. **Plain words.** UI copy is short, sentence case, second person, no "please", no exclamation marks, no jargon. Lesson text follows `docs/content/SPEC.md`. Public copy (home, About, For organisations, metadata) follows `docs/content/PUBLIC_COPY.md`: one mission statement (About's "Our mission" card holds the team's approved wording and nothing else), "social studies" with no hyphen, "youth" rather than "young people", and nothing promised that isn't true today.
7. **Ready for other languages.** Every UI string lives in `src/i18n/messages/en.json` (notes for translators in `en.notes.json`); never join translated strings in code, put English plurals in code, or format a date or number by hand (use `t`, `tx`, `formatDate`, `formatNumber`, `formatList` from `useI18n()`). The lessons stay in English on purpose, except in a language marked `content` (Bahasa Indonesia, for the Jakarta pilot), whose lessons, section checks, course text and pictures are translated too (`content/id/`, laid over the English files). Anything from `content/` shown in a page carries `contentLang` (or `<En>` inside a message), so it is marked `lang="en"` when the interface is in another language and the lessons are English; what stays English in every language (the videos' titles and channels) carries `englishLang` (or `<AlwaysEn>`). There is **one language setting** for the whole app, `useLearnerSession().language`, changed only with `setLanguage()`: the chosen learner's own language, else the device's (saved in Settings' storage before anyone is chosen). The header's language switch (every page, from the first), Settings, the new-learner form and the learner home all read and change it, and every page follows at once. Never add a second, separate language choice. Components read content through `useCatalog()` and `useContent()`, which give it in the language on screen, never the English module-level getters. Use CSS logical properties (`margin-inline-start`, not `margin-left`) and mirror direction icons in right-to-left. The languages are listed in `src/i18n/locales.ts`; only `ready` ones are offered: English and Indonesian. Dari/Farsi and Arabic (right to left, with Vazirmatn for Arabic script) and Somali are listed but not translated. Never put machine translation in front of learners: a native speaker translates and another reviews (`docs/TRANSLATING.md`). The one exception is Bahasa Indonesia: it was drafted by AI and is intentionally offered to everyone while native-speaker review is in progress (`docs/translation/README.md`). Details: `docs/notes/languages.md`.
8. **Honest.** Thinkerwell is a student-led platform and is not a registered charity or nonprofit. Don't claim otherwise anywhere. Public copy calls Thinkerwell a "platform", never a "project" (in Indonesian "platform", not "proyek"; `src/i18n/platformWording.test.ts`).

## Stack

- Vite, React and TypeScript (strict), with React Router. It is a static site hosted on Vercel, built with Node 22 (`engines` in `package.json`). `vercel.json` holds the build settings, the SPA rewrite (never for an address that ends in a file name), the caching headers and the security headers: a Content-Security-Policy that allows only this site plus the youtube-nocookie.com player in a frame, no referrer, no framing by other sites, and the microphone only here. `vite preview` sends the same headers, so the end-to-end tests run under the real policy. The import steps and every network request are in `docs/LAUNCH_CHECKLIST.md`.
- Plain CSS: `src/styles/tokens.css` (copied from `docs/design-system/tokens.css`) plus component CSS ported from `docs/design-system/reference/bundle.css`, keeping its `tw-` class names. No Tailwind, no CSS-in-JS.
- Icons: `lucide-react`. The design system uses Lucide names.
- Fonts, self-hosted (for example Fontsource packages): Funnel Display (headings), Atkinson Hyperlegible Next (everything else) and Eczar (the "Thinkerwell" wordmark only, cut down to its letters: `src/styles/fonts/`, made by `scripts/subset_wordmark_font.py`; `src/styles/fonts.test.ts` checks the wordmark needs no other letter). Latin and latin-ext files only. Fonts are never inlined as `data:` URLs (the Content-Security-Policy allows fonts only from this site). For Arabic script (Dari/Farsi, Arabic), Vazirmatn's Arabic letters are added to the first two families (`src/i18n/fonts/arabic.css`), loaded only while such a language is shown, as a stylesheet of its own: `src/i18n/fonts/index.ts` imports it with `?url` and adds a `<link>`, because the site's one stylesheet (`cssCodeSplit: false`) would take in a plain CSS import, and the build stops if Vazirmatn reaches it.
- On-device storage: IndexedDB through a small typed wrapper (`idb`).
- Offline: `vite-plugin-pwa` (Workbox) precaches the whole site (app, every page's code, every lesson and check, fonts, pictures, images) after the first page loads. The one thing cached at runtime is Listen's recordings (`/audio/`, this site's own files, too big for the precache), in a cache of their own (`docs/notes/recorded-audio.md`); YouTube and other servers are never touched. Other languages, and the Arabic font, are precached only once a language that needs them is `ready`, and the test languages never (`languagePrecacheIgnores` in `src/i18n/build.ts`). The worker is our own, `src/offline/sw.ts` (injectManifest): Workbox's precache and routes, but its install downloads six files at a time instead of one after another, which halves the time to "works offline" on slow connections. The app registers the worker itself (`src/offline/serviceWorker.ts`, production only): a new version waits and only starts when someone taps "Update now" (or the next time the site opens). Never make it reload by itself. Details: `docs/notes/phase-6.md`; sizes and times: `docs/notes/slow-internet.md` (`npm run slow-internet`).
- A first visit downloads only what its page needs (`docs/notes/slow-internet.md`). Home, the course map and the 404 are in the first chunk; every other page loads when first opened (react-router `lazy` through `lazyPage` in `src/app/lazyPage.tsx`, used by `src/app/routes.tsx`), in three chunks (`src/app/lazy/`): lessons and section checks; the Educators pages (teacher guides, answer keys, the setup checklist, the class view, all certificates, the partner kit), Credits, print views and the journal; Settings, About and certificates. If a page's code can't be downloaded (a first visit that lost the connection before the course was stored), the page says "This page hasn't downloaded yet" under the header with "Try again" (`src/pages/PageNotDownloaded.tsx`), never "Something went wrong"; only a failed download is caught that way (`isPageDownloadError`), and any other error still reaches `RouteErrorPage`. `main.tsx` keeps index.html's header bar until the first page's code is there. Once a service worker controls the page, `main.tsx` loads every page's code from the offline copy while idle. Pages on the first screen list lessons from `src/content/catalog.ts` (id, number, section, title, question, time, and each check's question count, made at build time); only lazily loaded pages import values from `src/content/index.ts`. The build stops if a lesson file, a lazily loaded chunk, a `src/dev` page or a source map would reach a first visit (`keepFirstVisitLight` in `vite.config.ts`). There is one stylesheet for every page (`cssCodeSplit: false`), so rules keep the order they had. A new page goes in one of the three chunks (`src/app/lazy/`, and `lazyChunkFor` in `src/app/lazy/firstPage.ts`), not a chunk of its own.
- First paint: until the app starts, `index.html` shows the header's lemon bar with the mascot (inside `#root`, drawn by the site's own CSS; React replaces it). On Slow 3G that is 2 s instead of 6 s of blank page. Keep it without words (UI strings live in en.json) and without anything that fetches ahead of the scripts.
- Content validation: `zod` schemas in `src/content/schema.ts`, checked by a test and whenever the content is built, served or tested (the content plugin in `vite.config.ts`, using `src/content/load.ts`). A problem stops the build. The browser never runs zod: `src/content/index.ts` uses the checked files as they are. App code imports only types from `schema.ts`; a value from it would bring zod into the bundle (and zod's `Function('')` check breaks the Content-Security-Policy), so the build stops if zod reaches a browser chunk.
- Tests: Vitest for logic, content and component behaviour (Testing Library), Playwright for end-to-end runs at 390, 820 and 1280px wide. Playwright blocks the service worker except in `e2e/offline.spec.ts` (`test.use({ serviceWorkers: 'allow' })`). `e2e/build-output.spec.ts` keeps the precache under 645 kB and a first visit to the home page under 221 kB (Brotli); look for a real cause before raising either, and write down by how much and why in `docs/notes/slow-internet.md`. A second, dev-only Playwright config (`playwright.dev.config.ts`, `npm run test:e2e:dev`) checks the `/dev/*` routes, which exist only in `npm run dev` and never reach `dist/`.
- Checks on every page type (phase 8): `e2e/pageTour.ts` visits every kind of page in one visit, and the no-sideways-scroll (320 to 1280px), axe and focus-ring, right-to-left, tap-size, privacy and Content-Security-Policy specs walk it. `e2e/languages.spec.ts` walks it in the test languages (en-XA, ar-XB) at 390px and fails on English text that isn't in en.json; the tour finds text by its en.json key (`e2e/uiText.ts`). Add a stop there when you add a kind of page. Tests that set their own window sizes are tagged `@own-size` and run in the laptop project only. Measure sideways scroll against `document.documentElement.clientWidth`, never `window.innerWidth` (an emulated phone zooms out to fit a page that is too wide).
- Search engines and link previews (`docs/notes/seo.md`): each public page (home, About, the course, For educators, For organisations, Credits, and each lesson's Read step) has its own HTML file with its own title, description, canonical link and link-preview tags, written at build time from `src/seo/` and en.json's `seo` (`seoFiles()` in `vite.config.ts`); `index.html` has only a `<!--page-metadata-->` marker for them. Every other address gets `app.html`, which says `noindex`. `vercel.json` serves them (rewrites, `trailingSlash: false`, and redirects from thinkerwell.vercel.app and www), and `vite preview` does the same. `public/robots.txt` and the built `sitemap.xml` list only the public pages. The public pages' tabs carry the same search titles (`useFullPageTitle`); other tabs are "<page> | Thinkerwell". A new public page needs an entry in `PUBLIC_PAGES`, its `seo` words in en.json, and a rewrite in `vercel.json`; the tests check they agree. Indonesian has no addresses of its own yet, so no `hreflang`.
- Later (not phase 1): Vercel Functions for `POST /api/events` and a Postgres database for pilot measurement. See `docs/research/MEASUREMENT_PLAN.md`.

Commands: `npm run dev` (dev server; add `?dir=rtl` to any URL to check right-to-left, or `?locale=en-XA` (accented and longer), `?locale=ar-XB` (right to left) or any listed language to see the interface in it; `?locale=en` turns it off), `npm run build`, `npm run typecheck`, `npm run lint` (ESLint and Stylelint), `npm test` (Vitest), `npm run test:e2e` (Playwright; run `npm run test:e2e:install` once), `npm run test:e2e:dev` (Playwright against the dev-only `/dev/*` routes; see README.md), `npm run check:content` (lesson, section-check and translation checkers; run `sh scripts/setup-python.sh` once for wordfreq and openpyxl), `npm run check:i18n` (translations against en.json), `npm run i18n:export -- <code>` and `npm run i18n:import -- <code> <file.csv>` (the translator's spreadsheet, `docs/TRANSLATING.md`), `npm run review:export` and `npm run review:import -- <file.xlsx>` (the Indonesian review spreadsheet, lessons included, `docs/translation/README.md`; `npm run test:review` tests them), `npm run size` (after a build: first load and precache sizes), `npm run perf` (after a build: page timings on Slow 3G, 3G and Slow 4G with a slow CPU), `npm run slow-internet` (after a build: first-visit and precache bytes by kind, and times to first paint, page ready and offline ready on Slow 3G and a very poor connection), `npm run check:audio` (Listen's recordings against the lessons; CI runs it) and `npm run audio:generate` (records them again with the voice models, on a computer that can run them: `scripts/audio/README.md`).

## Design system

- The brand book is `docs/design-system/README.md`; tokens are `docs/design-system/tokens.json` and `tokens.css`. Read the README before building any screen.
- `docs/design-system/reference/bundle.js` is a working reference implementation of every component (plain `React.createElement`), with its types in `index.d.ts` and notes in `docs/design-system/components/<Name>.md`. Port each one to a typed React component in `src/components/ds/` with the **same name, props and class names**. Behaviour the reference fakes (open states, pressed states) becomes real state and events.
- `docs/screens/*.dc.html` show every screen. Build pages to match them. If a screen and the design-system docs disagree, the docs win.
- Colour rules in short: lemon `#FFFF66` only for the header, the current step, the continue card and one highlight per screen, and never for text; one ink primary button per view; lavender means help; section colours (History amber, Geography sage, Culture rose, Civics sky) only in section places and always beside the section's icon and name; correct is teal, "not quite" is burnt orange. Cards use borders, not shadows. One exception, still to be confirmed: a learner's avatar colour is Yellow, Sand, Green, Blue or White, as on the NewLearner screen (see `docs/PRODUCT.md`).
- Don't redraw, recolour or crop the mascot. Use `public/images/thinkerwell-mascot-transparent.png` on coloured grounds.

## Content

- Lesson text comes only from `content/lessons/*.json`. Never hard-code lesson text in components, and don't edit it in code. To change a lesson, edit its JSON and run `python3 scripts/check_lesson.py content/lessons/*.json` (needs `pip install wordfreq`), which must report 0 errors. Quizzes: `python3 scripts/check_quiz.py content/quizzes/*.json`. When you change English learner text, the Indonesian goes stale: `npm run check:content` says which strings (each note in `docs/translation/id/notes/` keeps the English it was translated from as `source`). Update the Indonesian, or flag it for the reviewers, and its `source`.
- `id` is a stable slug used in URLs: `/lesson/:id/:stage`. `oldId` is the Base44 id; redirect `/lesson/l6` and the other old ids to the new URLs.
- "Next lesson" is worked out from the order, not stored.
- Quick-check options carry their own `correct` flag and feedback. Shuffle options with a seed per learner and question so the order stays the same when the learner comes back.
- Each glossary word is marked on its first appearance in each section, in both the standard and simpler text; tapping it opens the definition (`GlossaryTerm`). An entry may carry short meanings in other languages (`translations`, one line each, written by a native speaker); the popover shows the learner's under the English definition.
- Evidence with `fictional: true` shows its label ("Fictional example created for this lesson.").
- Notes for teachers are in two lists: `sensitiveNotes` (sensitive topics, what never to ask, which video to preview) and `educatorNotes` (everything else). Educator pages show the sensitive ones first, marked. Learners never see either.
- Write: show the example answer only after the learner has written something or asks to see one.
- Watch: embed from `youtube-nocookie.com`, only after the learner taps play, never autoplay. If the player hasn't loaded after 20 seconds, the device is offline, or "Save data" is on, show the written version. "Save data" is the Settings choice, or the browser's own data saver (`navigator.connection.saveData`) until someone chooses (`src/offline/saveData.ts`). Before the tap nothing may be requested from YouTube or Google (no thumbnails; the poster is drawn from the content). The iframe carries its own `referrerpolicy="strict-origin-when-cross-origin"`, because `index.html` sets `no-referrer` for the site and YouTube's player refuses to play without a referrer (Error 153). The content note goes only in a collapsed "For teachers" note.
- Reflect: the required prompt completes the lesson.
- When each stage counts as done is written down in `src/lesson/progressRules.ts`; change it there (and in `docs/PRODUCT.md`), not in the stage components. The course map, the learner home and the complete screen read the same saved `stagesDone`, `currentStage` and `completedAt`.
- The lesson player (`src/lesson/`, `src/pages/lesson/`) saves through `useLessonPlayer().update()`; never write lesson progress to IndexedDB from a stage directly. Look-around and "nobody chosen" keep work in memory only.
- `estimatedMinutes` is an estimate; show it as "About 30–50 min".
- Pictures: show `visual.src` inline in the Read stage near the evidence, with `visual.alt` as its alt text. They follow `docs/content/VISUALS_SPEC.md`; new pictures must too. "See it bigger" under each picture opens it in a native modal `<dialog>`, at least 640px wide (so its labels are at least 14px), with its area scrolling on a phone and pinch-zoom left on (`src/pages/lesson/visual/LessonVisual.tsx`). Never turn off pinch-zoom anywhere.
- Section checks (`content/quizzes/<section>.json`): one question at a time, shuffled options with per-option feedback, an optional `stimulus` (a short made-up example) shown above the question, and a results message chosen by score (high: at least 8 of 10 or 10 of 12; low: under half; otherwise middle). Questions are written to `docs/content/QUIZ_SPEC.md`.

## Data kept on the device

Version the schema and write migrations. Nothing is sent anywhere in phase 1.

- `learners`: id, name, colour, created date, optional class code, optional reading level (Standard or Simpler, last chosen), optional language (a code from `src/i18n/locales.ts`; the device's applies until then). For Indonesian it is the lessons' language too.
- `progress` per learner and lesson: stages done, current stage, warm-up answer, check answers, writing and planning notes, self-check ticks, how they practised speaking, reflections, completed date.
- `quizAttempts` per learner and section: answers, score, date (keep the best and the latest).
- `recordings` per learner and lesson: the latest audio clip only. Delete it when the learner is removed or taps Delete.
- `settings` per device: save data (`null` until someone chooses), listening speed, Listen's voice per lessons' language (`listenVoices`, missing for Automatic), preferred reading level, partner options, the last "Check this device" result for Say it (`speechCheck` for English, `null` until someone checks; `speechChecks` for another lessons' language, by speech tag such as `id-ID`), and the interface language for the home screen, guests and learners who haven't chosen (`language`, `null` for English). The optional fields were added without a new schema version: older records read as "no choice".

The journal is built from saved writing and reflections (`journalByLesson` in `src/storage/progress.ts`); it is not stored separately. Its print view is `/journal/print`; the journal page's "Print my journal" links there. Certificates are worked out from saved progress too (`lessonSetStatus`, `finishedSetWith`); nothing about them is stored.

**Moving work to another device** (Settings; `docs/notes/device-transfer.md`). "Save my work to a file" downloads one learner's `learners`, `progress` and `quizAttempts` records, or everyone's, as a JSON file (`src/storage/workFile.ts`: marker `thinkerwell-work`, `WORK_FILE_VERSION`, date saved). Recordings, `settings` and the current learner stay on the device. "Load my work" checks the whole file by hand (no zod in the browser), shows what is in it, and only after "Load it" merges it in one transaction (`importWork` in `src/storage/store.ts`, rules in `src/storage/mergeWork.ts`). Learners are matched by id, never by name, and nothing is lost. When these record shapes change, bump `WORK_FILE_VERSION` and keep loading older files, and update the checker and the merge rules. An optional field that older versions can simply drop (a learner's `language`) needs no new version.

## Listen, Say it and Record

The code is in `src/speech/`; browser support and the decisions behind it are in `docs/notes/phase-5.md`. Each feature shows only where it works; otherwise it is hidden, with no warning.

- **Listen** plays recordings of a natural voice, made ahead of time for everything it reads: every reading section, both reading levels, in English (Kokoro-82M, voice `af_heart`, speed 0.92) and Bahasa Indonesia (Meta's MMS-TTS, licensed CC BY-NC 4.0: non-commercial only, so it must be replaced before Thinkerwell ever charges; `docs/PRODUCT.md`). Details: `docs/notes/recorded-audio.md`. One MP3 per section, reading level and language in `public/audio/<lang>/`, with a timings file giving each piece's start and end; the app finds them through `src/audio/recordings.json`. A section's recording downloads only when Listen first plays it (and the next part's while one plays, not with Save data), then the service worker keeps it offline in a cache of its own; teachers download all of them in Settings ("Lesson audio", `/settings#lesson-audio`). They are never in the precache. Listen plays a recording only when its fingerprint matches what the section says now; the highlight follows the audio element's `currentTime` against the timings; Slow is `playbackRate` 0.8 with `preservesPitch` (and the webkit and moz names); Pause then Play starts the sentence again. **When lesson text that Listen reads changes, run `npm run audio:generate` and commit the new files**: `npm run check:audio` (in CI) fails until then. Never split sentences for the recordings any other way than `src/speech/sentences.ts`, which the app and the tools share.
- **Without a recording** (the language has none, not downloaded and offline, a file that fails, slower than 8 s, the text changed since it was recorded, or Save data on and not stored), Listen uses the browser's `speechSynthesis` with a voice that runs on the device (`voice.localService === true`) in the lessons' language: English, or Indonesian (`id-ID`) for a learner whose lessons are Indonesian. With neither a recording nor a voice, the Read step says why (`lessonPlayer.read.listenUnavailable`) and Listen turns off; never a button that does nothing. It never reads a language with another language's voice, never one of Apple's novelty voices, and never a voice documented as sending its text away, whatever `localService` says (`sendsTextAway`: "Online" or "-network" in the name, any "Google …" voice, and on a Chromebook any "Natural" voice, whose text Google's help says goes to Google). Listen shows where the lessons' language has recordings or the device has such a voice; with neither in an English lesson it is hidden, and in a translated lesson the Read step says so (`lessonPlayer.read.listenNoVoice`). Which voice: the one an educator chose in Settings ("Listen voice", `/settings#listen-voice`, saved per language in `settings.listenVoices`) if it is on this device, otherwise the best one by the ranking table in `src/speech/voiceRanking.ts` (quality from the name and `voiceURI`, then British English, then the device's default only to break ties; Safari calls every voice the default). A saved voice that has gone falls back to the best one without a word. In Settings, "Play a sample" plays the recorded sample sentence (or the device voice when it can't be had), and "Hear this voice" the chosen device voice, only on a tap. Reading `getVoices()` is fine as a page opens; speaking and playing happen only on a tap. Details and what each platform lists: `docs/notes/listen-voices.md`. It reads the version on screen from the first section to the last: the heading (with a full stop and a short silence after it, skipped when the first sentence repeats it), then one sentence per piece, and marks the current sentence with `mark.tw-speaking`. Speeds: Slow (about 0.8) and Normal (`settings.listeningSpeed`, saved only for a chosen learner); the pitch is the voice's own.
- **Say it** (dictation in Write, Watch and Reflect) listens in the lessons' language (`en-US`, or `id-ID` for Indonesian lessons: `speechLangFor` in `src/speech/language.ts`) and uses speech recognition only when the browser can do it on the device in that language: `SpeechRecognition.available({ processLocally: true })` must say `available`, and recognition then runs with `processLocally = true`. Other recognition may send audio to an online service. For children that is off unless an educator turns on "Allow online speech-to-text" on the Settings page (`/settings`, `settings.partner.allowOnlineDictation`). If neither applies, hide the button. The browser's one-time on-device download starts only from an educator's tap in Settings. Support changes often, so check it again when you touch this.
- **Never ask about speech recognition as a page opens.** Calling `available()` as Write, Watch, Reflect or Settings opened crashed the tab in Chromium 153 on touch devices. `available()` runs only when an educator taps "Check this device" in Settings, which saves the answer with the date (`settings.speechCheck`). Lessons decide from the saved settings alone (`dictationMode()`), and make a recognition object only when the learner taps Say it. `src/pages/speechOnOpen.test.tsx` checks this; end-to-end tests use the fake in `e2e/speechFake.ts` before tapping either.
- **Record yourself** (Speak) uses `MediaRecorder` and stores the latest clip per learner and lesson in IndexedDB. It is never uploaded. The microphone is asked for only when the learner taps Start, and the recorder is hidden where the device lists no microphone.
- Settings (`/settings`, in the header menu, outside the five main links) saves device settings even while looking around, because it sets up the device and isn't a learner's work. Inside lessons, look-around still saves nothing.

## Offline, Save data and print

Built in phase 6; see `docs/notes/phase-6.md`.

- After the first visit every lesson works offline. Under the header, `StatusBanner` says when the device is offline (tone offline) and, for five seconds, when it's back (tone back). Never tell a guest their work is saved.
- A new version shows "A new version is ready" with "Update now"; nothing reloads unless someone taps it.
- Settings for this device (`/settings`): offline status, Save data, moving work to another device (a file to save and load), the reading level for anyone who hasn't chosen one, the Listen speed, Listen's voice, the lesson audio (Listen's recordings for the device's lessons' languages, downloaded for offline use: not offered until the course is saved, nor with Save data on), and Say it ("Check this device", the on-device download and "Allow online speech-to-text").
- Every lesson has a print view (`/lesson/:id/print`, linked from Read): both reading levels, key words, the picture, the quick check and every task, black text on white with no header. Printing any page leaves out the header, menus and banners (`src/styles/print.css`).
- Certificates (`docs/notes/certificates.md`): one per section (`/certificate/section/:id`) and one for the course (`/certificate/course`), for a learner who has finished every lesson in it (section checks are never needed; no scores). Offered on the complete screen when that finish completes a section or the course, on a finished section's card on the course page, and on the learner home once the course is finished. The name can be changed for one print and is never saved. It prints on one landscape page that fits A4 and Letter, through a named page (`@page tw-certificate`), so other printouts stay portrait.
- Teacher tools (`docs/notes/teacher-tools.md`), linked from the Educators page: every lesson has a teacher guide (`/educators/lesson/:id`) and every section check an answer key (`/educators/section/:id/answers`). Each is one page for screen and paper, built on the print views' sheet. Everything in them comes from the content files. Correct answers are marked with a tick and the words "Correct answer", never by colour alone.
- Pilot-day tools (`docs/notes/pilot-day-tools.md`), linked from the Educators page: "Set up this device" (`/educators/setup`), a checklist that says which steps are done on this device and prints on one page; it never asks the browser anything that could prompt or crash as it opens (`persist()` only on a tap, the speech step from `settings.speechCheck`). "The class on this device" (`/educators/class`): every learner by name, lessons finished per section, where they are, last active, checks tried; never scores or a ranking, and no journal links. "Print all certificates" (`/educators/class/certificates`): every certificate earned on the device, one landscape page each. An optional step, "Choose the Listen voice", comes before the speech check (which stays last); the offline step points to Settings' "Lesson audio". Settings' Listen voice, lesson audio, Say it and moving-work parts have addresses of their own (`/settings#listen-voice`, `/settings#lesson-audio`, `/settings#say-it`, `/settings#move-work`).
- Credits (`/credits`, `src/pages/CreditsPage.tsx`, in the teacher pages' chunk), linked from the end of About and from the footer: every lesson's sources and video (from the lessons, links only, nothing embedded), pictures and the UN goal icons with the UN's statement, fonts, open-source software, Listen's recorded voices with their licences, and how the Indonesian was made. Add a library there when one that reaches the browser is added, and a voice when the recordings use another.

The form and the sheet promise what pilot measurement must keep to, in the same words (`pages.pilotStudy`): in the first and last sessions 16 questions, a few sentences on paper and 5 faces, and in every session how the learner uses Thinkerwell (time, lessons and steps, quick-check and quiz answers, the simpler reading and Listen, videos or reading instead, and word counts, never the words), which covers every in-app event in `docs/research/MEASUREMENT_PLAN.md`; the writing task is marked only by team members; all by code, never a name; seen only by the team, group results only to the organisation; deleted within 6 months of the pilot ending. ## Don't

- Add accounts, logins, a chatbot "Learning Guide", ads, analytics scripts or social embeds (the footer's LinkedIn link is a plain link: no LinkedIn script, feed or button).
- Load anything at runtime from a third-party server except YouTube embeds the learner starts. Adding a host to the Content-Security-Policy in `vercel.json` needs saying so in the pull request.
- Use red, lock lessons, add timers, or show learners a leaderboard.
- Put English strings straight into components.
- Change lesson text, the design tokens or the brand rules without saying so in the pull request.

## How to work here

- GitHub Actions (`.github/workflows/checks.yml`) runs every check (types, lint, unit tests, content, build, and the end-to-end tests at all three sizes) on each push to `main` and on every pull request. Keep it green.

- Work in small steps: one feature per branch and pull request. Run the tests and the content check before committing.
- Claude Code checks a lesson, a section check or an Indonesian file as soon as it edits one, with the same checkers as `npm run check:content` (`.claude/hooks/check_content_edit.py`, set in `.claude/settings.json`), and fixes any errors straight away. Run `sh scripts/setup-python.sh` once so the wordfreq checks run too.
- Test on narrow screens (390px) and with the keyboard as you go, not at the end.
- When a decision changes, update this file and `docs/PRODUCT.md` in the same pull request.
